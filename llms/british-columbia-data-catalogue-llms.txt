# British Columbia Data Catalogue

> The Government of British Columbia's open data catalogue, operated by DataBC. 3,356
> dataset records from 244 provincial ministries, agencies and public-sector bodies,
> organized into 26 thematic groups. Built on CKAN 2.9.5 and reachable through the CKAN
> Action API at https://catalogue.data.gov.bc.ca/api/3/action/ with no key and no account
> for public content. Its geospatial half is served separately as OGC WMS and WFS by
> DataBC at openmaps.gov.bc.ca, carrying 895 layers from the BC Geographic Warehouse.

Generated by API Evangelist on 2026-09-04 from this provider's own published contracts and
live API responses. The provider does not publish an llms.txt: every path on
catalogue.data.gov.bc.ca returns the same 37,599-byte HTML shell, including /llms.txt and
a control path that does not exist.

## How to call it

- Base URL: `https://catalogue.data.gov.bc.ca/api/3`
- Shape: RPC over HTTP. Every call is `/action/{action_name}`; there are no REST resource paths. Objects are named in the query string (`id`, `name_or_id`), not in the path.
- Auth: none for reads. Writes require a catalogue account and its token in the `ckan_api_key` header.
- Pagination: `limit`/`offset` on list actions; `rows`/`start` on `package_search`, whose `q` accepts Solr syntax and whose response carries `count` and `results`.
- Errors: the CKAN envelope `{help, error:{__type, message}, success:false}`. Branch on `success`, not on the status code. 409 means a validation failure, not a conflict. Malformed requests return a bare JSON string instead of the envelope. Not RFC 9457.
- Rate limits: none published, and no `RateLimit-*` or `Retry-After` headers are returned. The surface sits behind a Kong gateway, so throttling may exist without a runtime signal.
- Test environment: `https://cat.data.gov.bc.ca/api/3` answers anonymously.

## Key operations

- `GET /action/package_search` — search datasets with Solr, e.g. `q=res_format:wms`, `q=res_extras_bcdc_type:geographic`, `q=license_id:2`
- `GET /action/package_list` — every dataset slug
- `GET /action/package_show?id={slug}` — one dataset with all its resources
- `GET /action/organization_list` / `organization_show` — the 244 publishing bodies
- `GET /action/group_list` / `group_show` — the 26 thematic groups
- `GET /action/resource_search` / `resource_show` — individual distributions
- `GET /action/tag_list` / `tag_show` — catalogue keywords
- `GET /action/scheming_dataset_schema_show?type=bcdc_dataset` — the BC-specific field definitions the OpenAPI omits

## Crossing from metadata to data

A resource's `object_name` (for example `WHSE_LAND_AND_NATURAL_RESOURCE.PROT_CURRENT_FIRE_POLYS_SP`) is the BC Geographic Warehouse table name and is also the layer name in the DataBC WMS/WFS capabilities. That string is the join between a catalogue record and a live map service. 884 datasets carry a WMS resource.
